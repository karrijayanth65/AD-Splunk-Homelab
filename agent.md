# Project Editing Instructions

- Work only within the intended `AD-Splunk-Homelab` checkout. Inspect the branch, remote and local changes before editing or publishing.
- Read [Bible.md](Bible.md) for scope and decisions. Keep root instructions with this project.
- Maintain independently written documentation and editable design diagrams. Preserve technical meaning when rephrasing.
- Never present diagrams or generated images as captured execution evidence. Do not invent logs, results, dates, account identity or completed response actions.
- Keep personal execution claims separate from repository-validation claims. Ask for genuine missing artifacts before documenting a completed lab run.
- Do not add source screenshots or third-party code without checking reuse rights and required attribution.
- Keep configurations scoped to an isolated learning environment. Do not disable safeguards to obtain a test result.
- Validate local paths and exact casing, configuration structure and diagram rendering. Run relevant checks and inspect their actual results.
- Keep private captures, credentials, tooling downloads and backups outside Git. Review staged files before each authorized push.
- Publish only to the user-confirmed destination; no force pushes, repository deletion or unrelated changes. Report limitations rather than declaring a blocked check passed.
